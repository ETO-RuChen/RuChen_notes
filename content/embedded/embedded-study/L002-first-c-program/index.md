# 第 2 课：第一个 C 程序：按顺序得到确定结果

本课只建立一个核心概念：**最小 C 程序按语句顺序执行，并得到确定结果**。我们先在普通 Windows 主机上验证逻辑；没有开发板、目标工程或运行记录，因此这不是硬件验证。

## 1. 本节目标

完成本课后，你应该能在主机上阅读并修改一个单文件 C11 子集程序，说明它怎样按语句顺序完成一次确定计算，并通过程序的退出状态观察结果；同时能说明主机结果不能证明程序已经在嵌入式目标上运行。

预计用时 30 分钟。

## 2. 它解决什么问题

第一次看到 C 代码时，很容易只盯着符号，却不知道运行时先发生什么、后发生什么。本课把问题缩小到三个可观察的问题：

1. 程序从哪里开始执行本课代码？
2. 每条语句怎样改变当前结果？
3. 程序结束后，怎样在不依赖硬件的情况下看到结果？

当前没有具体开发板，所以实验不能依赖引脚、时钟、外设或调试器。我们用主机的退出状态承载一个小范围结果，只验证顺序计算逻辑。

## 4. 核心原理

最小程序不是“一次同时做完所有事情”，而是从 `main` 中第一条语句开始，一条接一条执行。前一条完整表达式产生的结果会在程序进入后续代码前生效；赋值会先计算右侧，再把结果保存到左侧指定的位置。[1]

- **解决什么问题**：让我们能预测程序每一步以及最终结果，而不是凭运行后的数字猜测。
- **对象在哪里定义**：要执行的语句和初始值都写在 `main.c` 的 `main` 中。
- **谁持有它**：源文件保存文字规则；程序运行时，当前的 `result` 值由这个正在运行的主机程序持有。
- **谁注入它**：本例没有外部输入；学习者把初始值 `4` 直接写入源文件，主机负责启动构建产物。
- **调用如何流动**：主机启动 `lesson.exe`，执行进入 `main`，语句依次把 `result` 从 `4` 变为 `7`，`main` 返回 `7`，PowerShell 再读取退出状态。

这里的“依次”是本课重点。若交换会依赖前一步结果的语句，最终结果可能改变；若源文件和输入不变，这个简单计算的预期结果也不变。

把 `result` 想成纸上的一个格子：第一条语句写入 `4`，第二条语句取出旧值、加 `3`，再把 `7` 写回同一个格子。`result` 是变量，也就是运行时可保存一个值的命名位置。

## 6. 从输入到结果的完整流程

1. 学习者把程序文字保存为 `main.c`。
2. GCC 读取源文件，生成主机构建产物 `lesson.exe`。本课只使用这个整体能力，不展开内部处理阶段。[2]
3. PowerShell 请求 Windows 启动 `lesson.exe`。
4. 程序进入 `main`，先执行 `int result = 4;`，此时 `result` 为 `4`。
5. 接着执行 `result = result + 3;`，先使用旧值 `4` 计算，再保存新值 `7`。
6. 最后执行 `return result;`，`main` 返回 `7`，进程结束，并把这个小范围值作为退出状态报告给父进程。[1]
7. PowerShell 中的 `$LASTEXITCODE` 显示最近一次本机程序的退出状态，预期为 `7`。

本实验特意不打印文本：这样可以集中观察“计算结果 -> 返回值 -> 退出状态”这一条路径。

## 9. 最小代码示例

将以下内容保存为 `main.c`：

```c
int main(void)
{
    int result = 4;
    result = result + 3;

}
```

这是单文件 C11 子集示例，不使用动态内存。代码属于主机逻辑验证层，依赖方向只有“主机启动程序并接收返回值”。本课不讨论 `int` 的宽度、表示范围或溢出，这些属于下一主题 `integer-model`。

## 10. 常见错误

- **从下往上读代码**：运行顺序是进入 `main` 后从第一条语句向后推进。
- **把第二行算成 `3`**：右侧 `result` 使用前一步保存的 `4`，所以新值是 `7`。
- **修改源文件后直接运行旧程序**：旧的 `lesson.exe` 不会自动包含新文字，必须重新构建。
- **只运行 `$LASTEXITCODE`**：它表示最近一次本机程序的状态，应紧接着运行 `lesson.exe` 后读取。
- **把 `7` 当成硬件证据**：它只来自 Windows 主机进程。
